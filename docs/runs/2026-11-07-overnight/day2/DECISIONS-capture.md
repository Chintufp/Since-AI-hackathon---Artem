# Decisions · B4 capture in front of the judge (D1 "Remember this", D2 Slack sandbox poller on a fake client)

Branch day2/b4 from run/2026-11-07-overnight at 67dcb3f. Each entry: decision, reason, how to reverse.

- D-B4-01 · Pasted threads are recognised by a pure sniffer, connectors/paste-thread.ts (detectPasteKind, parsePastedThread), in the order empty, JSON export with {messages}, e-mail, thread, note. Reason: the existing paste adapter stores one note with no speakers, so the rules extractor sees no claims by person. Reverse: route 'paste' straight to parsePaste again in memory/index.ts.
- D-B4-02 · E-mail means parseEmailHeaders finds a From, To, Subject or Message-ID header, not merely "a non-empty header block" as the brief says. Reason: 'Aarne: the link is up' parses as a header named 'aarne', so a plain two-speaker thread would have been taken for an e-mail. Reverse: test Object.keys(headers).length in detectPasteKind.
- D-B4-03 · Thread shapes: '[09:14] Name: text', '09:14 Name: text', 'Name  9:14 AM' or '[9:14 AM] Name' header lines followed by body lines, and plain 'Name: text' only with at least two different speakers and no timed line anywhere. Lines after a speaker line continue that message (multi-line messages keep their line breaks). A name is one to four capitalised words (lower-case particles such as 'van' allowed). Reason: a body line such as 'Did that at 9:20' must not open a new message, and inside a timed thread 'Note: counters zero' stays body text. Reverse: loosen NAME in paste-thread.ts.
- D-B4-04 · A 'Name:' line whose name is a common label (Problem, Steps, Status, Link, Note, Subject …, list LABELS in paste-thread.ts) is never a speaker, and free text before the first speaker line makes the whole paste a note. Reason: the brief forbids capturing a problem description as a thread; a labelled problem note ('Problem: … / Steps: …') would otherwise look like two speakers. Reverse: empty LABELS.
- D-B4-05 · Format 'paste' rides on POST /import (no new route; 40 routes stay 40). importSchema takes a string or {text, attachmentNames?, authorName?}, rejects blank text, a non-text payload and a path (a paste is inline only), and caps the text at 1 MB. A pasted thread or JSON export goes through parseTeamsJson with connection 'paste:desktop' and provider 'teams' (speakers bound by name to directory people); an e-mail through parseEmailText with the same connection; a note through parsePaste, whose author is authorName when given ('person:paste:<name>'), else 'Unknown author'. Attachment names are kept only on the note path. Reason: brief 4 B4 item 2. Reverse: drop 'paste' from both enums.
- D-B4-06 · ImportResponse gains an optional `captured` block, filled only for format 'paste' (other imports answer exactly as before). Case titles come from the case view seen with the import's own access groups; entities are the non-person entities the commit touched, people the person entities; from/to are the first and last stated stamps verbatim (no date is ever added); dateKnown is true only when a stamp states a full date with zone; alreadyKnown is inserted 0 and revised 0. importFromPath returns the ids behind its counts (optional `ids`), which Engine.importData strips from the HTTP response. The work lives in a new service file capture.ts so engine.ts changes by four lines. Reason: the receipt line needs names, not counts, without follow-up reads. Reverse: delete capture.ts and the field.
- D-B4-07 · Pasting a thread that is already in memory from another source (the seeded Elisa thread) is NOT 'Already captured': the twelve messages are new evidence under 'paste:desktop', marked as copies by the ingest copy detection, and bind to the same case (checked: same case id, copies 10). 'Already captured' means the same paste again. Reason: the copy lineage is the honest record (a second source retelling the same thread); collapsing it would hide where the knowledge came from. Reverse: set alreadyKnown when inserted equals copies.
- D-B4-08 · Panel "Remember this" is two entry points with one action: a footer text button next to Send (always there, enabled when Send is) and an offer chip in the input view shown only when the text sniffs as thread / e-mail / JSON export or a text file is attached. Cmd/Ctrl+Shift+Enter triggers it. Send (Enter) is unchanged and still investigates, so a problem description is never captured without the explicit click. Reason: brief item 3; a judge pasting a thread sees the offer, a person describing a problem never stores it by accident. Reverse: remove the button and chip from TEMPLATE.
- D-B4-09 · Files are read in the renderer with File.text() only when they are .txt/.eml/.json/.md (or a text/* , message/rfc822, application/json type) and at most 1 MB; each file is its own POST /import (a thread and an e-mail are different sources). Photos and other binaries stay as chips for Send and are listed as 'Not read' in the receipt; when nothing readable remains the receipt is 'Nothing to remember'. Reason: no vision model and no binary parsing locally; the service body cap is 5 MB. Reverse: widen TEXT_FILE in panel.ts.
- D-B4-10 · Access: the panel sends accessGroups = the current person's directory groups when they have any; a guest or a person with no groups imports org-wide. The note's author is the current person's name (authorName) when an identity is chosen; a pasted thread keeps its own speakers. Reason: the brief asks for the pasting person's groups so a paste on stage cannot leak beyond them; with no groups there is nothing narrower to give, and an org-wide paste is what the seeded demo already is. The service does not clamp accessGroups to a caller (ImportRequest has no principal), recorded as a known limit. Reverse: drop accessGroups from the body in remember().
- D-B4-11 · The receipt's time range joins the first and last stated stamps across all captured sources and always adds '(date unknown)' unless some stamp states a full date; 'Already captured' only when every source was already known.
