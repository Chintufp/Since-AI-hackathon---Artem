## E10: the store metric over a simulated day, LinUCB vs rules

Each arm uses a fresh demo store (synthetic), runs the demo:play day for 10 h in-process against the real service, and uses 3 seeds. Both selectors get the same day. Re-run after D-B2-66 (an applicability answer scopes the case, it is not a contradiction; supersedes D-B2-51) and D-B2-67 (questions ranked by value / cost); offline, rules only, no model, no network.

- Demo store before: 5 cases, completeness 0.45, correctness 0.0167. Only 1 of 60 case claims rests on ≥2 independent sources or an observed outcome; summed over 3 seeds that is 3/180. Product: 0.0075.
- After the day, on the same 5 cases, nothing has changed for either selector on any seed (gain 0 points; supported claims 3/180 → 3/180). Every question of the day touched the new train/validation cases: 5 cases become 17. Questions per point gained: undefined (n/a), because the same-case product did not move.
- Questions asked: 9 per selector (3 per seed, the same questions as before the change). Answered: rules 5/9, LinUCB 6/9. Measured per-answer product deltas: rules 0/5 negative and 0/5 positive (sum 0 points, was -6.77), LinUCB 0/6 negative and 0/6 positive (sum 0 points, was -13.54). Mean reward (delta minus burden): rules -0.008 (was -0.0215), LinUCB -0.0033 (was -0.0259); what remains is the burden term alone.
- The two scores apart (new, per answer, on the touched case): the applicability answers raised completeness on 3/5 answers for rules (sum +12.49 points: one key of four of the distinguishing slot is 1/24 = 4.17 points) and 4/6 for LinUCB (sum +16.66 points); correctness moved 0 points on every answer. The product does not move because every touched case has correctness 0 (no claim on ≥2 independent sources yet), so completeness x correctness hides the completeness gain, as the brief's product defines it. Questions per completeness point on the touched cases: rules 9/12.49 = 0.72, LinUCB 9/16.66 = 0.54.
- Per seed (product delta sum / completeness delta sum, points; mean reward): rules 1: 0 / 4.16, -0.01; rules 2: 0 / 8.33, -0.0067; rules 3: 0 / 0, null (nothing answered); LinUCB 1: 0 / 4.16, 0; LinUCB 2: 0 / 8.33, -0.0067; LinUCB 3: 0 / 4.17, 0.
- Bandit vs rules (frozen: a higher same-case gain per question on ≥2 of 3 seeds): LinUCB wins **0/3** (both gain 0 on every seed). Rules stay the default.
- Where a positive delta does come from: on the demo store, the RTR-117 outcome question ("Did the problem clear right after the earlier step on RTR-117?") answered Yes measures +2.25 points (the case's advice becomes supported; `tests/store-health.test.ts`). The simulated day's colleagues did not get such a question on a case with a supported claim.
