# Contract and library requests from the experiments worker (phase 2)

Nothing here blocks the experiments; each item was worked around in `experiments/` or recorded as a finding.

1. **Access: evidence refs of restricted evidence reach the requester.** `investigate()` builds `recommendation.basis`, `hypotheses[].basis` and `people[].reasons[].evidence` from the case's claims/attempts/outcomes without a per-evidence `canSee` check, while `buildCaseView` filters per item. Failing input: family `config-rollback-private` (train), requester `person:directory:elina-mattila` (groups `noc`), problems `config-rollback-private-p1` and `-p3`; shown evidence includes Slack `ts` 1783587900.000200, 1783588320.000300, 1783590000.000400 in channel C001CO (stored scope `group: slack-channel:C001CO`). Request: filter `EvidenceRef`s by the principal in investigation (or document that refs may name restricted evidence and must be resolved through a filtered view).
2. **`EvaluationRecord` needs the chosen action's benefit labelled by the caller.** The coordinator records `assessedBenefit: null` and later only a `response`; the harness labels benefit itself and keeps its own copy. Suggest a documented `label()` entry point (or accept `assessedBenefit` through `answer()`), so a learning loop does not need to re-read the store.
3. **Source id convention for scoring.** Adapters store Teams `<conversation>#<seq>`, email `msgid:<Message-ID>`, Slack `<channel>:<ts>`; the benchmark expects `teams:<seq>`, `email:<Message-ID>`, `slack:<ts>`. The harness converts (`benchmarkSourceId`). Request: state this mapping in `contracts/evidence.ts` or expose the conversion from the adapters.
4. **Question-to-condition mapping for outcome gaps.** Outcome gaps (`kind: outcome`) have no condition key, so a simulated person cannot be asked "which state key"; the harness translates to recovery-state keys. Request: give outcome gaps an optional `conditionKey` (for example the state the outcome question is about).
5. **Settings plumbing.** `defaultInvestigationSettings({questions})` replaces the whole `questions` object, so changing one field (`maxCandidates`) needs the caller to spread the defaults. A deep merge would avoid silent loss of templates.
6. **`pnpm test` does not cover `experiments/` or `benchmarks/`.** Add `'experiments/**/*.test.ts'` (8 tests) and `'benchmarks/**/*.test.ts'` (62 tests) to the package script (package.json is not mine to edit).
