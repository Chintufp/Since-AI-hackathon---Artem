## Data flow today

HOW /demo/activity.html IS SERVED TODAY: http.ts buildRoutes table key 'GET /demo/activity.html' -> engine.activityPage() -> activityPage() in activity-page.ts returns a string -> wrapped in `new HtmlResponse(html)` -> startHttp.send() sees instanceof HtmlResponse and replies 200 text/html with cache-control no-store. The browser then runs the inline script, which polls GET /demo/activity?since=N (engine.activity -> readActivity tails the JSONL data/local/demo-activity.jsonl, never written by the service) and GET /demo/clock (engine.clockStatus -> demoClock.status()). demo-judge.mjs opens http://127.0.0.1:47831/demo/activity.html with `open`.

WHAT /events AND TRACE EVENTS CONTAIN: GET /events -> engine.events({since,traceId}) -> store.list('trace') sorted by `at`, last 1000, mapped to ONLY {id, at, type, traceId} (data and actor stripped). The full TraceEvent {id, at (engine clock = demo clock, may be simulated), type, traceId, actor?, data?} is in the store. Types emitted: import.completed (engine.importData; data format, counts, cases, claims, people), investigation.started {principal{id,displayName,groups,type}, recommendation, basisCaseId} and investigation.rebuilt {observations, recommendation, basisCaseId} (investigate.ts, embedded in state.events and mirrored by Engine.sync), decision.recorded {decisionId, chosen, reason}, question.queued {questionId, personEntityId, decisionId}, question.answered {questionId, answerId, value}, question.deferred / question.dismissed {questionId} (coordinator.transition), question.cancelled {questionId, reason} (coordinator.cancelObsolete; engine.cancel adds by/reason), question.undone {questionId, restoredTo} (engine.undo), observation.recorded {observationId, key}, outcome.reported {reportId, result, lasting, decisionId?} (engine.recordOutcome), contact-draft.created {draftId, personEntityId, sent:false}, settings.updated {keys}, demo.reset, demo.clock {mode, now, rate}. traceId is the investigation id (inv_...) except 'settings' and 'demo'. simulation/runner.ts pollEvents consumes exactly these from /events.

ERKKI'S COST FROM SERVICE EVENTS: asked = question records with personEntityId = Erkki (store 'question', or question.queued events); answered = status 'answered' (Answer.at); seconds spent = Answer.at minus QuestionRecord.deliveredAt (fallback createdAt), already stored as EvaluationRecord.response.latencyMs (coordinator.answer), on the engine clock, so under the simulated demo clock these are SIMULATED seconds scaled by demo-clock rate (label it, or divide by rate); deferred/dismissed counted separately; reuse count by people and agents = distinct investigations (stable ids, so a repeated request is not recounted) whose investigation.started principal.type is 'human' or 'agent' and whose recommendation basis (state.recommendation.basis evidence authors, or hypotheses sourceClaimIds -> claim.assertedBy) is Erkki's claim, with recommendation kind in reuse/check-first/qualified. Nothing records 'reuse' directly today; either derive as above in a new Engine method or add an event. The activity page JSONL rows (kind question/answer/agent with detail.questionId, value, investigationId, agentId) are simulated-only and optional, so do NOT use them (brief says 'from service events'). Settings view: panel fetches via a new api route like loadPoints() does for GET /participation/rating.
