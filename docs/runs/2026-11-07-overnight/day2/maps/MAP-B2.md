INVESTIGATE: 'POST /investigate' -> Engine.investigate -> Engine.wiring() (per call: invSettings() merges EngineOptions.investigation and coordinator with the stored selectorId; new HybridRetriever(store, settings); RulesAssessor; TemplateQuestionGenerator; cached selector from createSelector; QuestionCoordinator) -> investigation/investigate.ts investigate(): parseProblemText -> await deps.retriever.search({text, conditions, entityIds, requesterPrincipal, k: settings.k=8}) -> retrieval/hybrid.ts Base.search: buildCorpus (access-gated case and procedure docs) -> resolveEntityIds -> lists() [bm25 w1 pruned 0.15, exact-id w1, trigram-hash w0.7 pruned 0.5] -> reciprocalRankFusion(k=60) -> top 2k -> toCandidate (compareConditions gives matching/conflicting/missing) -> condition-aware score -> mergeProcedures -> top k. Then assessor -> recommend -> gaps -> state.routes = uniqueRoutes([...]).

QUESTION: Engine.requestClarification / investigate with allowQuestions -> QuestionCoordinator.request: generator.generate(state, maxCandidates=4) (templates per open consequential gap) -> findRecipients + evaluateEligibility (hard gates) -> features() -> selector.select -> PolicyDecision stored -> EvaluationRecord {id = decision.id, assessedBenefit: null} stored -> QuestionRecord 'queued'.

ANSWER: 'POST /questions/:id/answer' -> Engine.answer -> coordinator.answer: Answer + attributed evidence + Observation (__answer:matches-case / differs) -> evaluation.response patched (benefit stays null) -> rebuild (re-investigate) -> recommendationChanged -> cancelObsolete. No selector.update anywhere live. Engine.answer then awards points (R46) and builds a receipt.

## Gotchas

- importFromPath (memory/index.ts) and Engine.importData are SYNCHRONOUS, and experiments/harness.ts prepareFamily relies on that. The LLM extractor is async, so you need an async import path (e.g. importFromPathAsync, or a post-import 'enrich' pass that runs the llm extractor on the same contexts and commits the union). The rules-only sync path must stay byte-identical when extract=rules.
- assignEpisodes mutates proposal.incidents[].key (asset:X becomes an episode key) before commit. An LLM proposal must get the same incident keys as the rules proposal for the same evidence, or it creates a second case: case id = stableId('case', org, key). Safest: take the incidents from the rules proposal and only add claims, entities and links from the LLM.
- Claims are bound to a case only when CASE_TYPES includes their type AND their first evidence id belongs to an incident that hasProblem. LLM claims whose first EvidenceRef is not in the rules incidents end up case-less.
- Union provenance: commitProposal uses proposal.route for every NEW claim and never relabels an existing one (base = prev). Two commits in a row (rules then llm) give per-claim provenance for free: rules-produced claims keep 'rules', llm-only ones get the ollama route. Committing llm first would label overlapping claims as llm.
- case-builder derives attempts and outcomes by re-parsing claim statements with inferActions/inferOutcome (rules lexicons). An LLM advice or action claim whose wording is outside the lexicon produces no attempt row, even though the claim is stored.
- Evidence-substring validator: excerpt must be a substring of the cited evidence text. Use the same text the rules extractor reads (context/extractionText(e), which may differ from e.text for quoted mail), and normalise whitespace consistently. Spans, if given, must satisfy text.slice(start,end) === excerpt or be dropped.
- HybridRetriever.Base.lists() is synchronous while search() is async. An embedding list needs the query embedded with await, so override search() or make lists async. Reasons strings key off list names ('bm25', 'trigram-hash'); add one for the embed list ('similar in meaning (local model bge-m3)'; never present cosine as confidence).
- The corpus is access-filtered per principal in buildCorpus. Embedding hits (cards, evidence, claims) must be intersected with the visible docs (byKey) and aggregated to 'case:<id>' keys, or a hidden case leaks into ranking. Evidence and claim rows must also pass evidenceGate.
- Engine.wiring() constructs a new HybridRetriever on every request. An embedding index must therefore be a cheap view over r_embedding and the provider (cache the provider client on the Engine), not rebuilt per call.
- KnowledgeStore has no vector/blob API, and the tests use InMemoryStore (models/testing/in-memory-store.ts) as well as SQLite.
